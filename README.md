# Лабораторная работа 1 по TCP/IP

**Стасев Б.В., ИТП-41. Вариант 1:** определить ранг квадратной матрицы размера N. Проверяющий — ассистент Башаримов Ю. С.

Приложение C# / .NET 8 вычисляет ранг локально и через три рабочих TCP-узла. Проект, исходные матрицы, отчёт и фактические результаты находятся в этой папке.

## Быстрый запуск в Docker Desktop

Откройте Docker Desktop в режиме Linux containers. Распаковывайте проект в путь с латинскими буквами, например `F:\psp-lab1`. На этом ПК уже создан такой путь к текущей папке проекта. В PowerShell:

```powershell
cd F:\psp-lab1
docker compose up --build
```

Будут запущены Linux-координатор и три Linux-узла в bridge-сети. Для матрицы 64×64 программа выведет `rank = 64` и `Ranks agree: True`, сохранит `results/linux.json`. Все четыре контейнера завершатся с кодом 0.

Проверочная матрица 4×4 имеет ранг 3. Для её запуска:

```powershell
$env:MATRIX_FILE = 'matrix.txt'
docker compose up --build
Remove-Item Env:MATRIX_FILE
```

Этот запуск перезапишет `results/linux.json`. Исходные результаты для отчёта сохранены также в `evidence/results`.

Удалить завершённые контейнеры и сеть данного проекта:

```powershell
docker compose down
```

## Запуск на Windows

На этом ПК уже установлен .NET 8 SDK. Сценарий собирает проект, запускает три рабочих процесса и координатор, затем проверяет завершение процессов:

```powershell
.\run-windows.ps1
```

По умолчанию используется матрица 4×4. Для замера на той же матрице, что в Docker:

```powershell
.\run-windows.ps1 -Matrix data/matrix-benchmark-64.txt -Result results/windows.json
```

## Windows и Linux вместе

Сценарий запускает координатор Windows и три Linux-контейнера; требуется работающий Docker Desktop:

```powershell
.\run-mixed.ps1
```

Узлы подключаются к координатору через `host.docker.internal:5000`. Результат — `results/mixed.json`, логи — `logs/mixed.out` и `logs/mixed-workers.out`. После демонстрации:

```powershell
docker compose -f docker-compose.linux-workers.yml down
```

Для ручного запуска сначала выполните `dotnet build -c Release`, затем запустите координатор:

```powershell
dotnet bin/Release/net8.0/DistributedRank.dll master --matrix data/matrix-benchmark-64.txt --workers 3 --port 5000 --repeat 5 --result results/mixed.json
```

Во втором окне:

```powershell
docker compose -f docker-compose.linux-workers.yml up --build
```

## Запуск на трёх физических компьютерах

Контейнеры на одном ПК демонстрируют сетевой обмен, но измерение на отдельных компьютерах ещё не выполнено. Проект готов для такого запуска. Скопируйте проект на три компьютера с .NET 8 SDK и выполните `dotnet build -c Release` на каждом.

На первом компьютере запустите master предыдущей командой и worker-1 в отдельном терминале:

```powershell
dotnet bin/Release/net8.0/DistributedRank.dll worker --host 127.0.0.1 --port 5000 --id worker-1
```

На втором и третьем запустите соответственно worker-2 и worker-3, указав вместо `192.168.1.10` реальный IPv4-адрес первого компьютера:

```powershell
dotnet bin/Release/net8.0/DistributedRank.dll worker --host 192.168.1.10 --port 5000 --id worker-2
dotnet bin/Release/net8.0/DistributedRank.dll worker --host 192.168.1.10 --port 5000 --id worker-3
```

У координатора должны быть разрешены входящие TCP-подключения к порту 5000 в локальной сети. На Linux команды `dotnet` те же. Координатор ждёт подключения узлов до 90 секунд; запускайте workers сразу после master.

## Входные данные и измерения

`data/matrix.txt` — пример 4×4 с зависимой второй строкой и рангом 3. `data/matrix-benchmark-64.txt` — плотная матрица `I + J`, где все элементы J равны 1. Собственные значения равны 65 и 1, ранг — 64.

Файл должен содержать квадратную матрицу конечных чисел. Разделители — пробелы, запятые или `;`, десятичный разделитель — точка. Пустые строки и строки с `#` игнорируются. Параметр master `--matrix` выбирает файл.

Ранг численный: допуск равен `1e-10 × max(1, max|aᵢⱼ|)`. Его можно изменить через `--tolerance`. Каждый режим выполняет один прогрев и `--repeat 5` измерений; выводится среднее. Подключение и запуск процессов исключены. Распределённое время включает передачу исходных строк и вычисление; отдельно выводится время после передачи строк. Все отдельные замеры, ОС и версия runtime сохраняются в JSON.

Фактические результаты и анализ — в `REPORT.md`, полные замеры — в `evidence/results`. Маленькая матрица выполняется локально быстрее из-за сетевых затрат.

## Протокол и проверка

Сообщения — UTF-8 JSON-объекты, по одному на строку TCP-потока. Worker отправляет `hello`, получает строки (`init`) и отвечает `ready`. Координатор собирает локальные кандидаты через `findPivot`, выбирает максимум по модулю, рассылает ведущую строку через `eliminate`, ждёт `ack`. Нулевой столбец пропускается. Завершение — `stop`. Строки назначаются узлам циклически; равные кандидаты выбираются по исходному номеру строки.

26 интеграционных проверок пройдены: расчёты через TCP сравниваются с точным рангом на рациональных числах, проверяются некорректные данные. При наличии Python:

```powershell
dotnet build -c Release
python tests/check_rank.py
```

Описание выполненных проверок — `evidence/verification.md`.

## Ошибка запуска Docker на этом ПК

Ошибка `initializing Secrets Engine ... engine.sock ... The file cannot be accessed by the system` была устранена 05.10.2026 сохранением двух папок временных сокетов при остановленном Docker, после чего Docker пересоздал их. Сохранённые папки имеют имена `run-stale-*` и `docker-secrets-engine-stale-*` в AppData. Работоспособность подтверждена сборкой и выполнением Linux- и смешанной конфигураций.

Если сбой повторится, сначала закройте Docker Desktop и убедитесь, что его процессы остановлены. Переименуйте `%LOCALAPPDATA%\Docker\run` и `%LOCALAPPDATA%\docker-secrets-engine` с добавлением уникального суффикса, затем запустите Docker Desktop. В данном случае папки содержали только временные файлы сокетов; перед переименованием проверьте содержимое. Образцы такого сбоя и восстановления описаны в [трекере Docker](https://github.com/docker/desktop-feedback/issues/554).

Ошибка сборки `x-docker-expose-session-sharedkey ... non-printable ASCII characters` здесь исчезла после запуска из `F:\psp-lab1` — используйте путь проекта с латинскими буквами.
